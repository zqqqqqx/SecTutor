用生活化的类比讲讲 SQL 注入是什么？
把数据库查询想象成一张「填空问卷」：程序写好句子，只留一个空让你填用户名。如果程序不检查你的输入，你填的「' OR '1'='1」就会改写成整句话的逻辑，让条件永远成立——于是绕过密码直接登录。 SELECT * FROM users WHERE name='' OR '1'='1' --' 防御核心：用参数化查询（预编译），让「填的内容」永远只是数据、不能变成代码。 参考来源：[1] 知识点·SQL 注入　[2] 知识点·预编译防御
那 XSS 和它有啥区别？
SQL 注入攻的是「数据库」，XSS 攻的是「别人的浏览器」。前者偷数据，后者在受害者页面上跑你的脚本——比如偷 Cookie、伪造操作。防御思路不同：XSS 靠输出转义 + CSP，而不是参数化。 参考来源：[1] 知识点·跨站脚本 XSS
